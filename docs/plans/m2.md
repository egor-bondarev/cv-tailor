# M2: Google-слой, парсер, сборщик запросов, проверка — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** детерминированная часть пайплайна без ИИ. Прочитать Google Doc, разобрать резюме на блоки, превратить операции в `batchUpdate` в режиме предложений, применить к копии и доказать, что текст и оформление стали ровно такими, как ожидалось.

**Architecture:** чистые функции над JSON `documents.get` (`docmodel`, `parse`, `requests`, `verify`, `naming`) плюс тонкая обёртка `google_api` с ограничениями доступа на основе папок Drive. Всё, кроме `google_api`, тестируется на синтетических документах без сети. Совпадение со спайком проверяется на сохранённых реальных данных. Сквозная проверка на живом Google — отдельный ручной скрипт.

**Tech Stack:** Python 3.11+, Pydantic v2, pytest, google-api-python-client, google-auth-oauthlib, PyYAML.

**Spec:** [DESIGN.md](../../DESIGN.md), разделы 8 (операции), 9 (Google), 10 (структура, запросы, проверка), 15 (критерий M2).

**Ревизия плана:** v2, после разбора `/critic` (2026-11-25). Что изменилось и почему — в разделе «Решения по критике» в конце.

## Global Constraints

- Python `>=3.11`; зависимости только из `pyproject.toml`: `pydantic>=2`, `pyyaml>=6`, `google-api-python-client>=2`, `google-auth-httplib2>=0.2`, `google-auth-oauthlib>=1`; тесты — `pytest>=8`.
- Пакет ставится `pip install -e '.[dev]'`; в `[tool.pytest.ini_options]` есть `pythonpath = ["src", "tests"]`.
- Индексы Docs API — в единицах UTF-16. Любая длина, прибавляемая к индексу, считается `utf16_len(s) = len(s.encode("utf-16-le")) // 2`, никогда `len(s)`.
- Все правки — один `batchUpdate` с `writeControl: {"requiredRevisionId": <revisionId копии>, "writeMode": "SUGGEST"}`; запросы по индексу по убыванию.
- `documents.get` вызывается без `includeTabsContent` (тело на верхнем уровне); проверка результата — с `suggestionsViewMode="PREVIEW_SUGGESTIONS_ACCEPTED"`.
- Scopes: `https://www.googleapis.com/auth/documents`, `https://www.googleapis.com/auth/drive`. Файлы `credentials.json`, `token.json` в корне репозитория.
- Тесты в `tests/` не ходят в сеть. Тесты на реальных документах лежат в `tests/private/` и пропускаются (`pytest.skip`), если нет `tests/fixtures/private/`. Личные данные (тексты резюме, названия компаний) встречаются только в `tests/fixtures/private/`, не в коде.
- Сообщения об ошибках на английском, с id блока или первыми 50 символами текста абзаца.

## Review Focus

1. **Не-BMP символы** (эмодзи) до или внутри правки: индексы сдвигаются на UTF-16 длину. Тесты: Task 3 `test_utf16_offsets_after_emoji`, Task 2 `test_block_indices_utf16`.
2. **Неидеальная разметка резюме:**
   - пустые абзацы;
   - мягкий перенос `\x0b`;
   - заголовок секции с пробелами или в другом регистре;
   - таблица;
   - лишний абзац без списка внутри роли;
   - вложенный буллет.

   Каждый непустой элемент получает блок, ничего не теряется. Тест: Task 2 `test_tolerates_messy_layout`.
3. **Незакрытые предложения в базовом резюме**: копия наследует их. Ожидание: `parse_resume` отказывается работать с понятной ошибкой. Тест: Task 2 `test_rejects_doc_with_pending_suggestions`.
4. **Новый процесс работает с копией, созданной раньше** (`final`, продолжение прогона): доступ определяется положением файла в Drive, а не памятью процесса. Тест: Task 6 `test_fresh_client_can_read_and_rename_earlier_copy`.
5. **Истёкший или отозванный токен**: исключение `AuthRequired`, `token.json` удалён. Тест: Task 6 `test_refresh_error_raises_auth_required_and_deletes_token`.

Правила разбора. Это решения плана; DESIGN 10.1 обновляется под них в Task 7.
- `has_suggestions(doc)` непуст → `ParseError("document has pending suggestions: …")`.
- Пустые абзацы (`body_text.strip() == ""`) блоков не дают. **Каждый непустой абзац и каждая таблица дают ровно один блок.**
- `TITLE` → `name` (readonly). `SUBTITLE` → `title` (editable). Остальные абзацы до первого `HEADING_1` → `contact.<NN>` (readonly).
- `HEADING_1/2/3` → `h.<NNN>` (readonly, сквозная нумерация). Имя секции = `body_text.strip().upper()`.
- Обязательны секции `SUMMARY`, `TECHNICAL SKILLS`, `EXPERIENCE`; нет любой → `ParseError("missing section: …")`.
- `SUMMARY`: ровно один непустой абзац → `summary`; больше → `ParseError`.
- `TECHNICAL SKILLS`: каждый абзац содержит `": "` → `skills.<slug(категория)>`, `label_len = utf16_len(text[: text.index(": ") + 2])`; нет `": "` → `ParseError`.
- `EXPERIENCE` и `EARLIER EXPERIENCE`, префикс `exp` и `early` соответственно:

  - `HEADING_3` → роль `slug(text.rsplit("|", 1)[0])`. В `EARLIER EXPERIENCE` роли нет: буллеты идут прямо после `HEADING_2`, роль = `None`, id `early.<c>.b<NN>`.
  - После `HEADING_3`: первый абзац без списка до первого буллета → `<p>.<c>.<r>.intro`. Абзацы со списком и `nesting == 0` → `<p>.<c>.<r>.b<NN>`. Со списком и `nesting > 0` → `<p>.<c>.<r>.b<NN>.s<K>` (readonly, NN — родительский буллет). Прочие абзацы без списка → `<p>.<c>.<r>.p<NN>` (readonly).

- Таблица → `table.<NN>`, `kind="readonly"`, `text` = текст ячеек.
- Повтор id компании, роли или категории skills → суффикс `-2`, `-3`.

### Task 3: Сборщик запросов

**Files:**
- Modify: `src/cvtailor/models.py` (добавить `Op`, `BuildError`)
- Create: `src/cvtailor/requests.py`, `tests/test_requests.py`, `tests/private/test_requests_real.py`

**Interfaces:**
- Consumes: `ParsedResume`, `Block`, `utf16_len` (Tasks 1–2).
- Produces:
  - `class Op(BaseModel)`: `id: int`, `op: Literal["replace", "replace_skills", "insert_after", "delete"]`, `block: str | None = None`, `after: str | None = None`, `new_text: str | None = None`, `new_value: str | None = None`, `evidence: list[str] = []`, `reason: str = ""`. Валидатор модели: `replace` — `block` + `new_text`; `replace_skills` — `block` + `new_value`; `insert_after` — `after` + `new_text`; `delete` — `block`.
  - `class BuildError(ValueError)`
  - `def check_ops(resume: ParsedResume, ops: list[Op]) -> None` — структурные правила ниже; `BuildError` на первом нарушении.
  - `def build_requests(resume: ParsedResume, ops: list[Op], mode: Literal["SUGGEST", "EDIT"] = "SUGGEST") -> dict` — вызывает `check_ops`; `resume.revision_id is None` → `BuildError`; тело `{"requests": [...], "writeControl": {"requiredRevisionId": resume.revision_id, "writeMode": mode}}`.

Правила:
- Цели: `replace` → `kind in {"title", "summary", "intro", "bullet"}`; `replace_skills` → `"skills"`; `insert_after`, `delete` → `"bullet"`. Блок `editable`. Иначе `BuildError` с id операции и блока.
- `new_text`/`new_value` непустые и без `\n`, `\r`, `\x0b`. Содержимое заменяемого блока может содержать `\x0b`, ограничение касается только нового текста.
- На блок не больше одной операции из `replace`/`replace_skills`/`delete`.
- **Якорь `insert_after` нельзя удалять.** `insert_after X` + `delete X` → `BuildError`. Причина: в SUGGEST-режиме диапазон удаления пересекал бы только что предложенную вставку. Замена якоря допустима: диапазон замены `[start, end-1)` заканчивается ровно там, где начинается вставка. DESIGN §8 правило 8 обновляется в Task 7.
- Запросы:
  - `replace` → `deleteContentRange [start, end-1)` + `insertText` в `start`;
