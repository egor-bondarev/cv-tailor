# M3: прогон от вакансии до документа с предложениями — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `cvtailor init` и цикл `cvtailor next` проводят прогон от текста вакансии до копии резюме с правками-предложениями, `review.md` и сводкой. ИИ участвует только в пяти шагах, всё остальное детерминировано.

**Architecture:**
- **Машина состояний** (`state.py`) хранит прогон в `runs/<run>/state.json`. Каждый вызов `next` выполняет детерминированные шаги подряд, включая Google API из M2, и останавливается на действии для агента: `ai`, `ask_user`, `say`, `auth` или `done`.
- **ИИ-шаги устроены одинаково:** Python собирает вход (`packs.py`), агент пишет JSON по промпту, Python проверяет схему и смысл (`schemas.py`, `checks.py`, `validate.py`). Служебные поля (`resume_id`, `base_revision`) подставляет Python, ИИ их не повторяет.
- **Конфигурационные ошибки ловятся до первого ИИ-шага.** Это соответствие ролей резюме ролям в `facts.json` и цитаты `used_in`; их проверка идёт на шаге копирования.
- **Ревью второй моделью** запускается подпроцессом во временной папке (`reviewer.py`).

**Tech Stack:** Python 3.11+, Pydantic v2, pytest, PyYAML; модули M1/M2.

**Spec:** [DESIGN.md](../../DESIGN.md), разделы 3–6, 8, 11, 13, 15.

**Ревизия:** v2 после `/critic` (2026-11-25). Решения по каждому замечанию — в конце.

## Global Constraints

- Всё из Global Constraints [плана M2](m2.md) в силе: UTF-16, SUGGEST, `requiredRevisionId`, тесты без сети, личные данные только в `tests/fixtures/private/`.
- В правки и во входы ИИ попадают только факты с `verified: true`, в том числе в `groups` и `covered_by`.
- `max_ai_retries` = 2. Для `tailor` после исчерпания попыток невалидные операции отбрасываются (жадный отбор, см. Task 3). Для остальных ИИ-шагов прогон блокируется действием `say`; снять блок можно `cvtailor next --from STEP`.
- `next` печатает действие одной строкой JSON в stdout, диагностика идёт в stderr.
- Лимиты по умолчанию — в `config.example.yaml` (DESIGN §8).
- Промпты на английском; вакансия может быть на любом языке.

## Review Focus

1. **ИИ не написал файл, написал мусор или агент вызвал `next` дважды.** Повторная выдача того же шага не тратит попытку, мусор тратит. Старые файлы не принимаются за новый ответ. Тест: Task 7 `test_reissue_without_output_does_not_burn_attempt`, `test_stale_output_is_moved_aside`.
2. **Числа-выдумки:** `40%` при метрике `42%`, `4` при `42%`, `3x`, `200ms`, `one of the`, `S3`/`OAuth2`/`v4.0`/`ISO 27001`. Сверка идёт по равенству токенов, числа с единицами тоже проверяются. Тест: Task 1 `test_number_tokens_cases`, Task 3 `test_numbers_rule_cases`.
3. **Сбой после `batch_update`.** Повторный `next` не применяет правки второй раз и не пишет «копию изменили». Тест: Task 7 `test_crash_after_apply_resumes_with_verify`.
4. **Названия компании или роли в резюме сокращены** по сравнению с `facts.json`. Сопоставление идёт по границам slug-токенов в обе стороны, при неоднозначности — ошибка конфигурации до ИИ-шагов. Есть ручная привязка через `resumes.yaml`. Тест: Task 1 `test_role_mapping`.
5. **Отбрасывание операций ломает правила для оставшихся.** Жадный отбор проверяет каждое добавление целиком. Тест: Task 3 `test_split_valid_greedy_rechecks_survivors`.

    - `WORDS = {"two": "2", …, "twelve": "12"}` — без `one`, чтобы «one of the» не становилось числом.

### Task 3: Валидаторы плана и жадный отбор

**Files:**
- Create: `src/cvtailor/validate.py`, `tests/test_validate.py`, `tests/private/test_validate_real.py`

**Interfaces:**
- Consumes: Tasks 1–2; `check_ops`, `BuildError`.
- Produces:
  - `class PlanContext(BaseModel)`:
    - `resume: ParsedResume`, `facts: FactsFile`, `resume_id: str`, `limits: Limits`;
    - `roles: dict[tuple[str, str], str]` (из `role_map`);
    - `covered: dict[str, list[str]]` (из `coverage`);
    - `protected: list[str]`.
  - `def validate_ops(ops: list[Op], ctx: PlanContext) -> list[CheckError]` — все нарушения набора.
  - `def split_valid(ops: list[Op], ctx: PlanContext) -> tuple[list[Op], list[tuple[Op, list[CheckError]]]]` — жадный отбор:
    1. операции по возрастанию `id`;
    2. операция принимается, если `validate_ops(принятые + [op])` не содержит ошибок с этим `op` и ошибок набора (`op is None`);
    3. иначе отбрасывается с этими ошибками.

    Итоговый набор всегда проходит `validate_ops` целиком.

Правила (номера = DESIGN §8):
1. **Цель.** `check_ops(resume, [op])` для каждой операции (`rule="target"`), затем `check_ops(resume, ops)` для сочетаний (`rule="combination"`, `op=None`). Ревизию проверяет не валидатор: `base_revision` подставляет Python.
2. **Evidence.**
   - Каждый id существует и проверен (`rule="evidence"`).
   - У `replace`/`insert_after` буллета или intro `evidence` непустой.
   - Роль: `ctx.roles[(company, role)]` совпадает с `role_id` каждого факта (`rule="role"`). Для `summary`, `title` и `skills.*` роль не проверяется.
3. **Числа** (`rule="numbers"`): каждый токен из `number_tokens(new_text, ctx.protected)` должен совпасть **по равенству** с токеном из `metric_tokens` фактов `evidence`. Для `replace` также допустим токен из `number_tokens` исходного текста этого блока. Для `replace_skills` правило не применяется: там нет метрик, работает правило 4.
4. **Строка skills** (`rule="skills"`):
   - `new_value` делится по `,` и `;` только вне скобок; у элемента снимаются префиксы `and `, `previous experience with ` и хвостовая точка;
   - скобки разбираются как подсписок, элементы проверяются так же;
   - проверяются только элементы, которых не было в исходном значении строки (после той же нормализации);
   - новый элемент — `name`/`alias` навыка с `basic: true` или хотя бы с одним **проверенным** фактом в `evidence`;
   - навык с `recency: previous` вне сегмента `previous experience with …` — ошибка.
5. **Заголовки** — обеспечено правилом 1.
6. **Длины** (`rule="length"`) по `Limits`; символы Python.
7. **Структура** (`rule="structure"`, `op=None`):
   - буллетов в роли после применения ≤ `max(max_bullets_per_role, исходное число)`;
   - операций ≤ `max_ops_per_plan`;
   - сумма длин редактируемых блоков после применения ≤ `total_editable_max_ratio` × исходной.
8. **Сочетания** — обеспечено правилом 1.
9. **Повторы фактов** (`rule="duplicate_fact"`, привязка к позднейшей по `id` операции):
   - факт из `evidence` операции `insert_after` или `replace` (буллета или intro) не должен покрываться (`ctx.covered`) блоком, который остаётся без изменений: не заменяется и не удаляется в этом наборе, и это не сама цель операции;
   - один факт не может быть в `evidence` двух таких операций.

### Task 4: Входы ИИ-шагов и промпты

**Files:**

- Produces (возвращают markdown; JSON в блоках ```` ```json ````):

  - `route_pack(vacancy: Vacancy, resumes: list[tuple[ResumeConfig, str]]) -> str`

- **ИИ-шаг.** Если `awaiting != step`, старый `output` (если есть) переименовывается в `<output>.stale<N>`, пишется pack, ставится `awaiting = step`, выдаётся `ai`. Если `awaiting == step`:
